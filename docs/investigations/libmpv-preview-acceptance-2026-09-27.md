# Windows 自定义页面 libmpv 改造与验收

日期：2026-09-27。基线分支 `fix/yulan`，基线提交 `d501e29a9376744a0fedb1d55ed87d8b157e33a0`。本次实现为本地未提交改动，无发布、版本升级或远端操作。

## 已实现

- Windows 自定义页面使用一个独立 C++ 辅助进程和 libmpv 原生子窗口。React 保留列表、时间轴和导出设置。直接加载已注册的媒体文件，不先转换完整视频；不经 JavaScript 逐帧搬运画面。
- `gpu-next` / D3D11 显示，自动硬解及软件回退；HDR 实时映射到 BT.709 / BT.1886 / 100 nit 的 SDR 预览。使用低成本缩放，不打开插帧与额外增强。
- 拖动每 45 ms 合并最新关键帧跳转，松手取消待发请求并精确跳转。序列号隔离过时请求；初始化、降级和切换片段保留最新播放位置及暂停意图。
- 比分由 mpv OSD 绘制，原生鼠标消息传回 React，支持拖动、四角缩放和快捷键。窗口缩放、175% DPI、最小化/隐藏及网页模态弹窗同步视频子窗口显隐。
- 首帧/跳转等待超过 8 秒，或播放时间停止推进 4 秒，按硬解、软解、局部代理顺序有限降级；明显低于实时速度时也降级。解码错误在软件重试仍失败后显示可重试错误，不无限转码。局部代理只生成目标所在的 6 秒、最多 640×360、30 fps 片段，预取下一片段，回报原片时间；缓存最多约 512 MiB，活跃文件短期保留。单片段生成有 45 秒硬超时和取消，不承诺低配机器上的代理也瞬时完成。
- 导入/历史打开使用交互式元数据探测：缺少容器帧数时保留 `null`，不执行整片 `-count_frames`。保留有界 VFR 包采样；分析/导出默认仍使用完整探测。
- 预览准备不再禁用已有合法选段的导出。导出继续使用原来的媒体选择和 FFmpeg 链路，不使用预览代理。
- 固定运行库及 SHA-256，随 Windows 包分发；`npm run stage:preview` 编译辅助进程，`prestart` / `stage:release` 接入。Windows C++ x64 Build Tools 仅构建机需要，用户电脑不需要另装 mpv。
- `--user-data-dir` 支持独立本地验收配置，避免修改用户原有历史记录。

范围为 Windows 自定义剪辑页面。校准页面原来的兼容预览、macOS 原生路径保持原有实现。

## 故障恢复、交互、导出

- 真实软件解码 `decoder=no` 验证保留位置及暂停状态。
- 人为把软件解码状态置为超时，随后执行真实生产 watchdog、FFmpeg、磁盘缓存及 libmpv 播放；目标 123 秒约 978 ms 恢复，仅生成 6 秒片段。跨 126 秒分片边界继续播放，远跳未生成的片尾也成功。触发故障是注入的，不声称现场 GPU 发生过硬件故障。
- 最后一轮同时运行全量测试和另一个完整应用包的组件检查，局部代理恢复耗时为 12.57 秒；该轮原片首帧仍为 647 ms。保留这个较慢结果：低清降级不是无条件秒开，机器并行负载会影响实际等待；正常原片路径不承担此转换成本。
- 真实鼠标拖动和四角缩放比分通过；网页模态确认框出现时隐藏原生视频、取消后恢复，通过桌面截图检查。
- 完整 TTcut 包使用真实历史记录的独立副本：从历史入口打开自定义页、播放/暂停、返回重开、时间轴点击及拖动后精确定位已验证。原历史数据未改写。
- 验收过程中修复了 mpv 嵌入 HWND 默认禁用导致点击穿透、OSD 分辨率整数参数、keep-open EOF 导致下一分片自动暂停、销毁窗口后读取 webContents 导致退出异常。相应场景已复测。
- 最终 `npm test`：493 项通过、25 项按现有条件跳过（70 个测试文件通过、6 个跳过）。`npm run typecheck` 通过，最终新增原生控制/拖动/快速探测回归 12 项通过。
- 实际 FFmpeg 导出集成测试通过：原片两段剪辑、H.264/AAC、时长与音视频流时长差、SSIM ≥ 0.95。既有比分烧录集成测试也包含在上述全量运行中。未执行本次真实识别算法或安装器测试。

## 使用与边界

本地可运行包：`output/native-preview-verified/TTcut-win32-x64/TTcut.exe`。必须保留整个目录，包含 `resources/libmpv`，不能只复制 EXE。

最终包及测试身份见 `output/native-preview-verified/acceptance.json`。`resources/app.asar` SHA-256 为 `e4ea467e90d07198d49d2459ec240c5ede2dc320ebb129d294641a7cd27509c3`；已逐项核对随包宿主/DLL 与 manifest，确认正常退出且没有残留播放进程。

回归入口：`scripts/verify-native-preview.mjs <原片...> [--recovery]` 与 `scripts/verify-packaged-native-preview.mjs <打包EXE> <历史记录JSON>`；后者复制记录到独立 profile。`--hold` 用于桌面交互检查，在标准输入发送一行后关闭。

运行库版本 `20260927-git-a1bf4b6559`，DLL SHA-256 `0a81c004aae0ee7d512b9a26e38f66281f9591e84e1663215cc3a36a4bde6f6a`。具体构建及宿主摘要见随包 `resources/libmpv/manifest.json`。上游许可及来源见 `resources/libmpv-licenses`；这是本地验收包，正式公开分发仍需把完整固定构建及其依赖的对应源码和许可纳入发布材料。

没有声称任何损坏文件、任意 8K 高帧率素材或所有低配显卡都能实时播放。本次没有 8K、跨 GPU、多显示器不同 DPI、专业 HDR 色彩仪测量或客观音画同步误差测量。已测量的是这些样本在本机的首帧、可持续播放、跳转与交互；软件/低清降级及有限错误退出避免再次把全片转换作为通用前提。
