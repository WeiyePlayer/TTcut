# ADR 0013：回合识别方式独立于分析精度，并对结果分型

## 状态

已接受

## 背景

落台事件不足时，现有按落台分组的流程可能没有回合，即使球在一段时间内持续可见。分析精度解决的是轨迹推理成本和覆盖范围，而落台事件与连续可见是两种不同的回合语义；将它们混成一个设置会令历史重放、批量导出和筛选合同不稳定。

## 决策

1. 增加独立的 `rally_recognition_method` 设置，默认 `bounce_events`；缺失或非法旧设置迁移为该默认值。
2. Worker 请求 schema v3 显式携带 `rally_recognition.method`。v1/v2 继续按落台判定解释。
3. 分析结果升级为 schema v2 并按识别方式分型。落台结果保留板数与落台时间；连续可见结果不含这些字段，且记录使用的迟滞阈值。
4. 连续可见固定完整单阶段分析并跳过所有落台检测。基础候选边界是首个及最后一个可见帧，确认迟滞不加入边界。
5. 基础候选还需通过分辨率归一化的交换运动筛选：可靠的水平往返可直接成立；水平跨度足够且垂直轨迹简单的短球作为兜底。中值平滑抑制孤立跳点，超过固定时长的检测缺口不得制造方向反转。
6. 两个已通过运动筛选的候选仅在不可见间隔和边界位移都受限时桥接；合并后的边界仍取两端真实可见帧。新结果记录运动筛选与桥接阈值，读取旧连续可见结果时允许这些溯源字段缺失。
7. 精彩筛选使用显式 criterion：落台结果只接受板数 criterion，连续可见结果只接受时长档位 criterion。旧 `highlight_threshold` 规范化为落台 criterion。
8. 渲染、历史和自定义时间轴根据结果自身的识别方式决定是否显示板数；不得依赖当前设置。

## 结果

- 现有用户保持原来的默认落台行为，旧历史继续可打开和导出。
- 连续可见结果可在单视频和批量流程中使用相同状态机、交换运动筛选、遮挡桥接与时长档位，但不提供两阶段高精分析。
- 结果契约通过判别字段阻止板数数据被错误用于连续可见回合，代价是调用方必须处理联合类型。
